# Hospital Data Analysis

This repository contains focused, reproducible analyses of hospital patient data using `pandas` and `matplotlib`. Use a separate notebook for each source type: CSV, Excel, and SQLite.

## Repository Contents

- `data/raw/hospital_original.csv` — Preserved raw dataset. Treat this source as read-only.
- `data/raw/hospital_original.xlsx` — Excel copy of the hospital dataset, used by the Excel notebook.
- `data/hospital.db` — SQLite database with the `hospital` table, used by the SQL notebook.
- `data/cleaned/hospital_cleaned.csv` — Validated cleaned dataset generated by the notebook.
- `data/backups/` — Timestamped data copies, including the notebook's versioned cleaned backup.
- `hospital_analysis_csv.ipynb` — CSV-specific analysis; defaults to `data/raw/hospital_original.csv`.
- `hospital_analysis_excel.ipynb` — Excel-specific analysis; set the workbook path and sheet in the configuration cell.
- `hospital_analysis_sql.ipynb` — SQLite-specific analysis; reads the database in read-only mode.
- `hospital_analysis.ipynb` — Previous combined notebook retained as a legacy reference; use one of the three source-specific notebooks instead.
- `requirements.txt` — Reproducible package requirements.

## Dataset Overview

Expected columns (surrounding whitespace is trimmed):

- `Patient_ID` — Unique identifier for the patient
- `Age` — Patient age (numeric)
- `Gender` — Categorical (e.g., Male/Female/Other)
- `Condition` — Primary diagnosis/condition
- `Medication` — Medications prescribed
- `Admission_Date` — Admission date (day-first format expected)
- `Discharge_Date` — Discharge date (day-first format expected)
- `Patient_State` — State or region of residence
- `Year_of_Admission` — Year (numeric)
- `Length_of_Stay` — Length of stay in days (numeric)
- `Readmission` — Yes/No indicator
- `Outcome` — e.g., Recovered/Deceased/Other
- `Satisfaction` — Satisfaction score (numeric)
- `Insurance_Claimed` — Yes/No indicator
- `Total_Cost` — Numeric cost value (currency-free)

If column names differ by whitespace or capitalization, the notebook strips and normalizes them at load time.

## Goals of the Analysis

The `hospital_analysis.ipynb` notebook performs a short, easy-to-follow exploration that:

- Checks that the preserved raw data exists and has all required columns before loading it.
- Validates duplicate patient IDs, negative ages/costs, fixed-format dates, and discharge dates before admission.
- Cleans the raw data without overwriting it, then saves `data/cleaned/hospital_cleaned.csv` and a timestamped copy in `data/backups/`.
- Presents the first 10 rows and basic `df.info()` / `df.describe()` statistics.
- Performs simple analyses on financials, demographics, and length-of-stay:
  - Summary statistics for `Total_Cost` and top conditions by average cost.
  - `Age` distribution and `Gender` counts.
  - Distribution and top conditions by average `Length_of_Stay`.
- Visualizes results with concise `matplotlib` charts: bar charts and histograms with labels for quick interpretation.

## How to Run

1. Open this folder in VS Code, Jupyter Notebook, or JupyterLab.
2. Open the notebook matching the source format:
   - `hospital_analysis_csv.ipynb` for CSV
   - `hospital_analysis_excel.ipynb` for Excel
   - `hospital_analysis_sql.ipynb` for SQLite
3. Run its cells top-to-bottom to load and validate the selected source, clean and save a separate output copy, print summary statistics, and produce plots.

## Selecting a Data Source

Each notebook has a source-specific configuration cell:

- **CSV:** Set `CSV_PATH`; the default is `data/raw/hospital_original.csv`.
- **Excel:** Set `EXCEL_PATH` and, if needed, `EXCEL_SHEET_NAME` (a sheet name or zero-based sheet index). Excel input uses `openpyxl`.
- **SQL:** The notebook supports SQLite databases. The included `data/hospital.db` contains the `hospital` table. Set `SQLITE_DB_PATH` and `SQL_TABLE_NAME`, or provide a `SELECT` in `SQL_QUERY`. Analysis opens the database in read-only mode. If the default database is missing, the setup cell creates it once from the project CSV.

To create a SQLite database from the included CSV once, run:

```python
import sqlite3
import pandas as pd

records = pd.read_csv("data/raw/hospital_original.csv")
with sqlite3.connect("data/hospital.db") as connection:
    records.to_sql("hospital", connection, if_exists="replace", index=False)
```

Each notebook validates the core hospital columns before analysis. Other database servers (such as MySQL or PostgreSQL) are not configured yet; they need their own connection settings and appropriate database drivers.

## Failure Points and Recovery Plan

This is an offline analytical prototype, not a production hospital information system. It currently relies on local files and has no automated restore service.

- **Single point of failure:** local CSV data; deletion, corruption, unauthorized modification, and privacy exposure are risks.
- **Recovery:** keep `data/raw/hospital_original.csv` read-only, use the separate cleaned file, retain versioned backups, and regularly test opening a backup before restoring it.
- **Backup practice:** keep three copies on two storage types, with one copy stored separately from the project folder. A backup in the same folder does not protect against disk failure or ransomware.
- **Restore process:** copy the latest verified backup to `data/raw/hospital_original.csv`, confirm its required columns and file integrity, then restart the kernel and run the notebook from top to bottom.
- **Production upgrade:** use a database with role-based access, encryption, audit logs, automated backups, and a documented disaster-recovery plan.

Notes:

- The notebook uses `pandas` and `matplotlib` for the analysis. Restart the kernel and run all cells top-to-bottom before submission to avoid stale results.
